### 实施（commit message 先行）

| 顺序 | commit message | 内容 |
|---|---|---|
| 1 | `ci: add manual APK build workflow` | 新增 `.github/workflows/manual-apk.yml`：`workflow_dispatch` 输入 `build_type`（debug/release）+ `run_gate`；debug 直接 `assembleDebug`，release 解码 `RELEASE_*` Secrets 后 `:app:assembleRelease`；产物按版本 + 短 SHA 重命名并生成 `SHA256SUMS.txt`，上传 artifact（14 天） |
| 2 | `docs: document manual APK workflow and sync status` | `CLAUDE.md` 新增「CI（GitHub Actions）」节；`git-workflow.md` 补 CI 工作流；`release-checklist.md` 补「获取验证包」；`docs/README.md` 更新索引；订正 `todo.md` / `action-plan.md` 过时状态；`CHANGELOG.md` Unreleased |

### 实施决策

- **动作版本对齐本仓**：沿用 `ci.yml` / `release.yml` 的 `checkout@v4` / `setup-java@v4`（含 gradle 缓存）/ `upload-artifact@v4`，不采用 Float 的 v5/v6/v7，保持仓库内一致
- **签名口径复用 release.yml**：`RELEASE_KEYSTORE_BASE64` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD` / `RELEASE_STORE_PASSWORD`，`RELEASE_STORE_FILE=../release.keystore`（相对 `app/` 解析，与 `app/build.gradle.kts` 的 env 回退一致）
- **默认不跑 gate**：与 Float 一致——手动工作流只打包，`run_gate` 按需开启
- **不绑定 push/tag**：仅手动触发，避免空跑消耗 Actions 额度

### 验证

- `manual-apk.yml` 经 YAML 解析校验通过（1 job / 9 steps / 2 inputs）
- 工作流不改动 Gradle 构建；本地全量 gate 复核见下
